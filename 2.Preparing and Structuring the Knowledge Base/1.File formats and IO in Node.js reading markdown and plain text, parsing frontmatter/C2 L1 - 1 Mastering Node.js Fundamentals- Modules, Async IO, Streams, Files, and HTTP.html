Node is JavaScript with bindings to the underlying operating system, enabling JavaScript programs to interact with files, processes, and networks. Node excels as a modern alternative to shell scripts, a general-purpose language for trusted programs, and a popular environment for concurrent web servers. Its key feature is single-threaded, event-based concurrency, supported by an asynchronous API.
Node Programming Basics
Node programs interact with the operating system using console output, command-line arguments, environment variables, and modules.
Console Output
In Node, ‘console.log()’ is the standard way to display messages. ‘console.error()’ writes to the ‘stderr’ stream, distinguishing it from ‘console.log()’ output, which goes to ‘stdout’.
Command-Line Arguments and Environment Variables
Node programs access command-line arguments via the ‘process.argv’ array. The first element is the Node executable path, the second is the JavaScript file path, and subsequent elements are command-line arguments.
‘’‘javascript console.log(process.argv); ‘’’
Environment variables are available through the ‘process.env’ object.
‘’‘javascript console.log(process.env); ‘’’
Program Life Cycle
Node executes JavaScript files from top to bottom. Programs continue running until all callbacks are called and there are no pending events. ‘process.exit()’ can force an exit, and Ctrl-C can terminate a program unless a signal handler is registered. Uncaught exceptions print a stack trace and exit the program, but this can be avoided by registering a global handler function:
‘’‘javascript process.setUncaughtExceptionCaptureCallback(e => { console.error(“Uncaught exception:”, e); }); ‘’’
Unhandled Promise rejections can be handled with a global handler function:
‘’‘javascript process.on(“unhandledRejection”, (reason, promise) => { // Handle unhandled rejections }); ‘’’
Node Modules
Node uses the ‘require()’ function to import values and the ‘exports’ object or ‘module.exports’ property to export values. ES6 modules are supported, but Node needs to know whether a module is CommonJS or ES6 before loading it.
•
.mjs extension: Node loads it as an ES6 module.
•
.cjs extension: Node treats it as a CommonJS module.
For files without these extensions, Node checks the package.json file for a ‘type’ property with values “module” or “commonjs”.
Node Package Manager
npm (Node Package Manager) manages libraries and dependencies. It uses a package.json file in the project’s root directory.
‘’‘javascript npm install express ‘’’
This command downloads the Express library and its dependencies into the node_modules/ directory and records the dependency in package.json.
Node Is Asynchronous by Default
Node is designed for I/O-intensive programs and achieves concurrency with a single-threaded programming model. It uses asynchronous, nonblocking APIs by default, even for filesystem operations.
Node uses error-first callbacks, typically invoked with two arguments: an error (or ‘null’ if no error occurred) and the data produced.
‘’'javascript const fs = require(“fs”);
function readConfigFile(path, callback) { fs.readFile(path, “utf8”, (err, text) => { if (err) { console.error(err); callback(null); return; } let data = null; try { data = JSON.parse(text); } catch(e) { console.error(e); } callback(data); }); } ‘’’
The ‘util.promisify()’ wrapper can create Promise-based variants of callback-based APIs.
‘’'javascript const util = require(“util”); const fs = require(“fs”); const pfs = { readFile: util.promisify(fs.readFile) };
async function readConfigFile(path) { let text = await pfs.readFile(path, “utf8”); return JSON.parse(text); } ‘’’
Node also defines blocking, synchronous variants of many functions, labeled with ‘Sync’ at the end.
‘’‘javascript const fs = require(“fs”); function readConfigFileSync(path) { let text = fs.readFileSync(path, “utf8”); return JSON.parse(text); } ‘’’
Node uses event-based asynchrony for streaming data, with a single thread running an “event loop”.
Buffers
The Buffer class is a sequence of bytes, similar to a string. It is a subclass of Uint8Array and is designed to interoperate with JavaScript strings.
Encodings in Node are specified by name, such as ‘“utf8”’, ‘“utf16le”’, ‘“latin1”’, ‘“ascii”’, ‘“hex”’, and ‘“base64”’.
‘’'javascript let b = Buffer.from([0x41, 0x42, 0x43]); b.toString(); // => “ABC” b.toString(“hex”); // => “414243”
let computer = Buffer.from(“IBM3111”, “ascii”); for (let i = 0; i < computer.length; i++) { computer[i]–; } computer.toString(“ascii”); // => “HAL2000” computer.subarray(0, 3).map(x => x + 1).toString(); // => “IBM”
let zeros = Buffer.alloc(1024); // 1024 zeros let ones = Buffer.alloc(128, 1); // 128 ones let dead = Buffer.alloc(1024, “DEADBEEF”, “hex”); // Repeating pattern of bytes
dead.readUInt32BE(0); // => 0xDEADBEEF dead.readUInt32BE(1); // => 0xADBEEFDE dead.readBigUInt64BE(6); // => 0xBEEFDEADBEEFDEADn dead.readUInt32LE(1020); // => 0xEFBEADDE ‘’’
Events and EventEmitter
Objects that emit events are instances of EventEmitter or a subclass. The ‘on()’ method registers event handler functions.
‘’'javascript const EventEmitter = require(“events”); const net = require(“net”); let server = new net.Server(); server instanceof EventEmitter; // => true
server.on(“connection”, socket => { socket.end(“Hello World”, “utf8”); }); ‘’’ The ‘emit()’ method invokes the registered event handler functions. Event handling functions are invoked synchronously. “Error” events get special treatment: if there are no handlers registered for that event type, an exception will be thrown.
Streams
Streams process data in small chunks, making them memory-efficient.
Node supports four basic stream types:
•
Readable: Sources of data.
•
Writable: Destinations for data.
•
Duplex: Combines Readable and Writable streams.
•
Transform: Data written becomes readable in transformed form.
By default, streams read and write buffers. The ‘setEncoding()’ method of a Readable stream returns decoded strings instead of Buffer objects.
Pipes
The ‘pipe()’ method connects a Readable stream to a Writable stream.
‘’'javascript const fs = require(“fs”);
function pipeFileToSocket(filename, socket) { fs.createReadStream(filename).pipe(socket); } ‘’’
Transform streams are useful with pipes.
‘’'javascript const fs = require(“fs”); const zlib = require(“zlib”);
function gzip(filename, callback) { let source = fs.createReadStream(filename); let destination = fs.createWriteStream(filename + “.gz”); let gzipper = zlib.createGzip();
source .on(“error”, callback) .pipe(gzipper) .pipe(destination) .on(“error”, callback) .on(“finish”, callback); } ‘’’
Asynchronous Iteration
Readable streams are asynchronous iterators in Node 12 and later.
‘’'javascript async function grep(source, destination, pattern, encoding=“utf8”) { source.setEncoding(encoding); destination.on(“error”, err => process.exit());
let incompleteLine = “”;
for await (let chunk of source) { let lines = (incompleteLine + chunk).split(" "); incompleteLine = lines.pop(); for(let line of lines) { if (pattern.test(line)) { destination.write(line + " ", encoding); } } } if (pattern.test(incompleteLine)) { destination.write(incompleteLine + " ", encoding); } } ‘’’
Writing to Streams and Handling Backpressure
The ‘write()’ method takes a buffer or string as the first argument and returns ‘true’ if the internal buffer is not yet full, or ‘false’ if it is. A return value of ‘false’ is a form of backpressure.
‘’'javascript function write(stream, chunk, callback) { let hasMoreRoom = stream.write(chunk);
if (hasMoreRoom) { setImmediate(callback); } else { stream.once(“drain”, callback); } } ‘’’
Reading Streams with Events
Readable streams have two modes:
•
Flowing mode: Data is immediately emitted as “data” events.
•
Paused mode: Data is pulled by explicitly calling the ‘read()’ method.
Flowing mode
Registering a “data” event handler switches a stream into flowing mode.
‘’'javascript const fs = require(“fs”);
function copyFile(sourceFilename, destinationFilename, callback) { let input = fs.createReadStream(sourceFilename); let output = fs.createWriteStream(destinationFilename);
input.on(“data”, (chunk) => { let hasRoom = output.write(chunk); if (!hasRoom) { input.pause(); } }); input.on(“end”, () => { output.end(); }); input.on(“error”, err => { callback(err); process.exit(); });
output.on(“drain”, () => { input.resume(); }); output.on(“error”, err => { callback(err); process.exit(); }); output.on(“finish”, () => { callback(null); }); } ‘’’
Paused mode
In paused mode, the stream does not push data. Instead, you pull data from the stream by explicitly calling its ‘read()’ method.
‘’'javascript const fs = require(“fs”); const crypto = require(“crypto”);
function sha256(filename, callback) { let input = fs.createReadStream(filename); let hasher = crypto.createHash(“sha256”);
input.on(“readable”, () => { let chunk; while((chunk = input.read())) { hasher.update(chunk); } }); input.on(“end”, () => { let hash = hasher.digest(“hex”); callback(null, hash); }); input.on(“error”, callback); } ‘’’
Process, CPU, and Operating System Details
The global Process object and the “os” module provide low-level details about the running Node process and the operating system.
Process object properties and functions:
‘’‘javascript process.argv; // Command-line arguments process.arch; // CPU architecture process.cwd(); // Current working directory process.env; // Environment variables process.exit(); // Terminates the program process.platform; // Operating system process.version; // Node’s version string ‘’’
“os” module functions:
‘’‘javascript const os = require(“os”); os.arch(); // CPU architecture os.cpus(); // System CPU cores data os.freemem(); // Free RAM in bytes os.homedir(); // Current user’s home directory os.platform(); // Operating system os.totalmem(); // Total RAM in bytes os.type(); // Operating system type ‘’’
Working with Files
Node’s “fs” module provides a comprehensive API for working with files and directories, complemented by the “path” module. The “fs” module includes nonblocking, callback-based asynchronous functions, synchronous blocking variants, and Promise-based asynchronous variants.
Paths, File Descriptors, and FileHandles
Files are specified by path, which includes the file name and directory hierarchy. Absolute paths specify directories from the filesystem root, while relative paths are meaningful in relation to the current working directory.
‘’'javascript process.cwd(); // Current working directory __filename; // Absolute path of the current file __dirname; // Absolute path of the current directory
const path = require(“path”); path.sep; // Directory separator path.normalize(“a/b/c/…/d/”); // => “a/b/d/” path.join(“src”, “pkg”, “t.js”); // => “src/pkg/t.js” ‘’’ ‘’‘javascript path.resolve("/a", “/b”, “t.js”); // => “/b/t.js” ‘’’
Algunas funciones de “fs” esperan un file descriptor (descriptor de archivo) en lugar de un nombre de archivo, obtenido llamando a ‘fs.open()’ o ‘fs.openSync()’. Los file descriptors deben cerrarse con ‘fs.close()’ cuando se terminen. La API basada en Promise usa objetos FileHandle en lugar de file descriptors.
Lectura de Archivos
Los archivos se pueden leer de una vez, mediante un stream (flujo), o con la API de bajo nivel.
Lectura del contenido completo de un archivo con una sola llamada:
‘’'javascript const fs = require(“fs”); let buffer = fs.readFileSync(“test.data”); // Síncrono, devuelve buffer let text = fs.readFileSync(“data.csv”, “utf8”); // Síncrono, devuelve string
fs.readFile(“test.data”, (err, buffer) => { if (err) { // Manejar el error aquí } else { // Los bytes del archivo están en buffer } });
fs.promises .readFile(“data.csv”, “utf8”) .then(processFileText) .catch(handleReadError);
async function processText(filename, encoding=“utf8”) { let text = await fs.promises.readFile(filename, encoding); // … procesar el texto aquí… } ‘’’
Lectura de un archivo mediante un stream:
‘’‘javascript function printFile(filename, encoding=“utf8”) { fs.createReadStream(filename, encoding).pipe(process.stdout); } ‘’’
Usando la API de bajo nivel:
‘’'javascript const fs = require(“fs”);
fs.open(“data”, (err, fd) => { if (err) { // Reportar error de alguna forma return; } try { fs.read(fd, Buffer.alloc(400), 0, 400, 20, (err, n, b) => { // Manejar los datos leídos }); } finally { fs.close(fd); } }); ‘’’
Escritura de Archivos
Los archivos se pueden escribir de una vez, mediante un stream, o con la API de bajo nivel.
Escritura del contenido completo de un archivo con una sola llamada:
‘’'javascript fs.writeFileSync(path.resolve(__dirname, “settings.json”), JSON.stringify(settings));
fs.appendFileSync(“messages.log”, “hello”, { flag: “a” }); ‘’’
Escritura de un archivo mediante un stream:
‘’‘javascript const fs = require(“fs”); let output = fs.createWriteStream(“numbers.txt”); for(let i = 0; i < 100; i++) { output.write(’${i} ‘); } output.end(); ‘’’
Usando la API de bajo nivel:
‘’'javascript const fs = require(“fs”);
fs.open(“data”, ‘w’, (err, fd) => { if (err) { // Reportar error de alguna forma return; } try { fs.write(fd, Buffer.from(‘data to write’), 0, Buffer.from(‘data to write’).length, 0, (err, n, b) => { // Manejar los datos escritos }); } finally { fs.close(fd); } }); ‘’’
Operaciones con Archivos
El método ‘fs.copyFile()’ copia archivos.
‘’'javascript fs.copyFileSync(“ch15.txt”, “ch15.bak”);
fs.copyFile(“ch15.txt”, “ch16.txt”, fs.constants.COPYFILE_EXCL, err => { // Manejar finalización });
fs.promises.copyFile(“Important data”, ‘Important data ${new Date().toISOString()}’, fs.constants.COPYFILE_EXCL | fs.constants.COPYFILE_FICLONE) .then(() => { console.log(“Backup complete”); }) .catch(err => { console.error(“Backup failed”, err); }); ‘’’
La función ‘fs.rename()’ mueve y/o renombra un archivo.
‘’‘javascript fs.renameSync(“ch15.bak”, “backups/ch15.bak”); ‘’’
La función ‘fs.unlink()’ elimina un archivo.
‘’‘javascript fs.unlinkSync(“backups/ch15.bak”); ‘’’
Metadatos de Archivos
La función ‘fs.stat()’ obtiene metadatos de un archivo o directorio.
‘’‘javascript const fs = require(“fs”); let stats = fs.statSync(“book/ch15.md”); stats.isFile(); // => true stats.isDirectory(); // => false stats.size; // tamaño del archivo en bytes stats.atime; // tiempo de acceso stats.mtime; // tiempo de modificación ‘’’
Funciones como ‘fs.chmod()’, ‘fs.chown()’ y ‘fs.utimes()’ se usan para cambiar metadatos de archivos.
Trabajo con Directorios
La función ‘fs.mkdir()’ crea un nuevo directorio.
‘’‘javascript fs.mkdirSync(“dist/lib”, { recursive: true }); ‘’’
La función ‘fs.rmdir()’ elimina un directorio, pero debe estar vacío.
La función ‘fs.readdir()’ lista el contenido de un directorio.
‘’'javascript let tempFiles = fs.readdirSync("/tmp"); // devuelve un array de strings
fs.promises.readdir("/tmp", {withFileTypes: true}) .then(entries => { entries.filter(entry => entry.isDirectory()) .map(entry => entry.name) .forEach(name => console.log(path.join("/tmp/", name))); }) .catch(console.error); ‘’’
Clientes y Servidores HTTP
Los módulos “http”, “https” y “http2” de Node implementan clientes y servidores HTTP.
‘’'javascript const http = require(“http”);
http.get(“http://example.com”, response => { response.on(“data”, chunk => { console.log(chunk.toString()); }); }); ‘’’
Las funciones ‘http.request()’ y ‘https.request()’ hacen peticiones HTTP.
‘’'javascript const https = require(“https”);
function postJSON(host, endpoint, body, port, username, password) { return new Promise((resolve, reject) => { let bodyText = JSON.stringify(body);
let requestOptions = { method: "POST", host: host, path: endpoint, headers: { "Content-Type": "application/json", "Content-Length": Buffer.byteLength(bodyText) } }; let request = https.request(requestOptions); request.write(bodyText); request.end(); request.on("error", e => reject(e)); request.on("response", response => { response.setEncoding("utf8"); let body = ""; response.on("data", chunk => { body += chunk; }); response.on("end", () => { try { resolve(JSON.parse(body)); } catch(e) { reject(e); } }); });
}); } ‘’’

Working with Child Processes
The “child_process” module defines functions for running other programs as child processes.
execSync() and execFileSync()
The ‘child_process.execSync()’ function runs a command in a shell and blocks until it exits.
‘’‘javascript const child_process = require(“child_process”); let listing = child_process.execSync(“ls -l web/*.html”, {encoding: “utf8”}); ‘’’
The ‘child_process.execFileSync()’ function executes a program directly without invoking a shell.
‘’‘javascript let listing = child_process.execFileSync(“ls”, ["-l", “web/”], {encoding: “utf8”}); ‘’’
exec() and execFile()
The asynchronous functions ‘child_process.exec()’ and ‘child_process.execFile()’ return immediately with a ChildProcess object.
‘’'javascript const child_process = require(“child_process”); const util = require(“util”); const execP = util.promisify(child_process.exec);
function parallelExec(commands) { let promises = commands.map(command => execP(command, {encoding: “utf8”})); return Promise.all(promises) .then(outputs => outputs.map(out => out.stdout)); } ‘’’
spawn()
The ‘child_process.spawn()’ function provides streaming access to the output of a child process.
fork()
The ‘child_process.fork()’ function runs a module of JavaScript code in a child Node process.
‘’'javascript const child_process = require(“child_process”);
let child = child_process.fork(’${__dirname}/child.js’);
child.send({x: 4, y: 3});
child.on(“message”, message => { console.log(message.hypotenuse); child.disconnect(); }); ‘’’
Worker Threads
Node allows true multithreaded programming with the “worker_threads” module. Worker threads communicate by message passing instead of shared memory.
‘’'javascript const threads = require(“worker_threads”);
if (threads.isMainThread) { module.exports = function reticulateSplines(splines) { return new Promise((resolve, reject) => { let reticulator = new threads.Worker(__filename);
reticulator.postMessage(splines); reticulator.on("message", resolve); reticulator.on("error", reject); });
}; } else { threads.parentPort.once(“message”, splines => { for(let spline of splines) { spline.reticulate ? spline.reticulate() : spline.reticulated = true; }
threads.parentPort.postMessage(splines);
}); } ‘’’
