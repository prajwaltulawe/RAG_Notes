Grouping Sentences Using Cosine Similarity
In this article, I’ll explain how I used cosine similarity to create groups of similar sentences.
I was given the following problem: the chatbot can’t understand all sentences. So, I needed to take all the sentences that weren’t understood and group them by context, then add responses for each context so the chatbot could handle these new situations.
At first, I thought: “Finally, the time has come to use all that machine learning, artificial intelligence, and data science buzzwords knowledge I’ve studied over the past few years!”
I started reading a lot about text similarity algorithms and found some that had all the buzzwords I wanted to use, but they weren’t that simple to apply. The problem wasn’t that they were difficult, but that they took a long time to test, and only afterward would I know if I was using the right algorithm. Since I’m working at a startup, time is still crucial, so I couldn’t just spend weeks testing machine learning algorithms to figure out which one would actually solve my problem. That’s why I decided to hold back my urge to use “rocket science” and went for simpler things, build an MVP of it, and put it into production. If we later feel the need for something more robust, I saved the links to those machine learning algorithms… you never know… lol.
Cosine Similarity
The cosine similarity algorithm is what I used to compare 2 sentences. It compares the words in 2 texts, ignoring order, and creates a vector with the most repeated words. Then you just apply the formula and “it’s done.” Here’s an example:
Please, what is the daily rate?
Please, what is the price of the drink?
We break them into words, so we’ll have the following vector:
[“por”, “favor,”, “qual”, “o”, “valor”, “da”, “diária”, “bebida”]
Now we’ll count how many words from the vector are in each sentence

Cleaning the Sentences
The first time I ran the script, I saw several groups of similar sentences and was really happy. But upon deeper analysis, I saw that most of them didn’t make sense to be grouped together, because even though they looked very similar, they meant different things and I couldn’t give a similar response to the whole group. Also remember to add both correctly spelled and misspelled words because you have to compare with what the user writes… so you’ll get all possible and unimaginable ways to write the same word.
Now, after cleaning the sentence before running cosine similarity, we get the following result:
const str1 = 'Por favor, qual o valor da reserva?'
const str2 = 'Por favor, qual o valor da diária?'
const str3 = clearText(str1) // reserva
const str4 = clearText(str2) // diaria
Cosinesimilarity(str1, str2) // 0.857142857142857
Cosinesimilarity(str3, str4) // 0.0
After using text cleaning, we got a 0% similarity between the two sentences. In the context I’m working with, these 2 sentences really aren’t similar. Depending on the context, the word ‘valor’ might make sense, so removing it from “wordExcluded” gives a 50% similarity. That’s why you need to really understand the context you’re working in.
What is an acceptable similarity?
As soon as I started testing, I used 80% similarity and it seemed like a human had read all the sentences and grouped them. However, many sentences with similar contexts weren’t being grouped. So, I kept lowering it by 5% at a time until I reached a point where too many nonsensical sentences were coming in, and in my context, the ideal value was 60%. With 50%, I had a large group of similar sentences, but still a lot of “junk” within the groups. With 55%, it decreased a lot, but 60% felt the safest to work with, as I had a large number of sentences per group and all of high quality. With 80%, the quality was incredible, but few sentences per group. For a group to be valid and go to production, it needed at least 5 sentences per group, and in that case, it was hard to get a group with 5 or more sentences.
Remember, these values are in the context I’m working in; in another context, an acceptable value might be 90%, and in another, it could be 50%.
One of the things that motivated me to write this post is that nowadays everything is machine learning, artificial intelligence, data science, data mining, and we don’t always need to do something so complex to solve a problem that “apparently” needs something complex. I don’t know who told me this, but if you’re doing something very complex to solve a problem, you’re probably doing it wrong. Also, it wasn’t worth spending weeks developing this feature using state-of-the-art technology without knowing if my users would even stop by at least once a month to see the misunderstood sentences and add a response to them. If this MVP works out and I later need some “buzzwords,” I’ll write a new post about how to improve the text similarity algorithm.
