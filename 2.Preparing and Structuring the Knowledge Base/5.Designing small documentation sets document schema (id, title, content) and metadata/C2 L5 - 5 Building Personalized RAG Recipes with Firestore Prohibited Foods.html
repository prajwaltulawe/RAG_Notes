Food Fit 2.0: Customize Your Recipes with RAG Using Genkit and Firestore
In the first part, we built Food Fit, an app capable of generating healthy recipes using Genkit, Gemini, and Imagen 3.
In this second part, we’ll add a new feature: customizing recipes based on the user’s dietary restrictions, by implementing a RAG (Retrieval-Augmented Generation) pattern using Firestore as a knowledge repository.
Why RAG in an App Like Food Fit?
In the initial version, the app generated recipes solely based on the ingredient entered by the user. However, a problem arose:
What happens if the user can’t consume certain ingredients due to allergies or restrictions?
This is where RAG becomes key.
What is RAG?
RAG (Retrieval-Augmented Generation) combines a generative model with external information stored in a database or additional service.
Its main goal is to prevent the AI from “hallucinating” and force it to rely on real, specific data.
How Does RAG Work in Simple Terms?
•
The user enters a food item.
•
We retrieve the user’s information from Firestore (restricted foods).
•
We inject that information into the prompt as context.
•
The model generates recipes considering both the user’s input and their restrictions.
For this example, we’ll store the foods the user can’t consume and instruct the model not to include them in the generated recipes.
Is It Really RAG If We Don’t Use Vectors?
Yes, but in its lightest version.
We don’t implement traditional RAG based on embeddings and vector searches. Instead, we apply contextual RAG, which is very common when data is structured:
•
Retrieval: comes from Firestore.
•
Augmentation: we inject that data directly into the prompt.
•
Generation: Gemini produces the recipe while respecting the restrictions.
Application Architecture
In this new version, the app isn’t just composed of Angular and Genkit. Now we also incorporate:
•
Firebase Authentication, to identify the user.
•
Firestore, to store restricted foods.
Step-by-Step Implementation
Now that we understand the why and the concept behind lightweight RAG, let’s see how to implement it in our app.
User Authentication
Before customizing any recipe, we need to identify the user. With Firebase Authentication, each user gets a unique UID, which we’ll use as the key to store their dietary restrictions.
This ensures that: Each user has their own profile, their preferences are isolated, and we can apply RAG consistently.
Saving Dietary Restrictions in Firestore
We create a collection:
/prohibited-food/{uid}
Where each document contains the list of foods the user can’t consume:
{ "foods": ["milk","peanuts"] }
Implementing the RAG Flow in Genkit
To implement dietary restrictions within the recipe generation process, we create a flow in Genkit called foodSuggestionWithProhibitedFoodFlow. This flow encapsulates two important steps:
•
Retrieval: Get the list of user-restricted foods from Firestore.
•
Augmented Generation: Build a context and pass it to the Gemini model to generate the recipes.
export const foodSuggestionWithProhibitedFoodFlow = ai.defineFlow( { name: 'foodSuggestionWithProhibitedFoodFlow', inputSchema: inputSchemaWithProhibitedFood, outputSchema: outputListFoodItemSchema, }, async (payload) => { try { // We retrieved the user information from Firestore const userDoc = await db.collection('prohibited-food').doc(payload.userId).get(); if (!userDoc.exists) { throw new UserFacingError('NOT_FOUND', 'No user data found.'); } const prohibitedFoods = userDoc.data()?.foods; // We build a context that we then inject into the model const prohibitedFoodsContext = prohibitedFoods.length > 0 ? `The user is allergic to: ${prohibitedFoods.join(', ')}. **MAKE SURE TO EXCLUDE THESE INGREDIENTS. IF THE USER SPECIFIES A FOOD FROM THIS LIST AS THE MAIN INGREDIENT, DO NOT GENERATE ANY RECIPE.**` : 'No known allergies.'; // We explicitly send instructions within the system and prompt so that the model strictly follows those restrictions. const suggestionPrompt = ai.prompt('foodSuggestionWithProhibitedFood'); const { output } = await suggestionPrompt({ ...payload, prohibited_foods_context: prohibitedFoodsContext }); if (output == null) { throw new UserFacingError('UNAVAILABLE', 'There was an error generating the recipe.'); } return output; } catch (error) { throw new UserFacingError('UNAVAILABLE', error) } } );
This flow retrieves the list of prohibited foods for a user from Firestore and automatically builds a context that warns the model to exclude those ingredients and not generate recipes if any appear as the main ingredient. It then sends these instructions to the model prompt along with the original input data to generate a safe food suggestion. If the user doesn’t exist or the model doesn’t return a valid response, the flow throws a UserFacingError indicating the issue.
