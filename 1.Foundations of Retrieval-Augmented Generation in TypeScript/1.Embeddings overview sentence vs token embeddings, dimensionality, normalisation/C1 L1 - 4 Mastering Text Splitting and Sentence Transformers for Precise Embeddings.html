Tokens vs. Characters: Prefer Token-Based Chunking for Embeddings Models like SentenceTransformers
Introduction
When working with large documents or text data, embedding techniques play a crucial role in summarizing or analyzing content efficiently. One of the most popular models for embeddings is Sentence Transformers, which builds upon BERT.
BERT and Sentence Transformers
What is BERT?
BERT (Bidirectional Encoder Representations from Transformers) is a transformer-based model designed to embed tokens (words or subwords) into dense vectors, capturing the semantic meaning of each token. However, BERT only embeds individual tokens and may not be optimal for longer sequences like sentences or documents. It processes one token at a time and doesn’t combine token embeddings into a single sentence or document-level vector.
What are Sentence Transformers?
Sentence Transformers extend BERT by allowing you to embed entire sentences or small documents into a single vector. This is done by pooling (aggregating) token-level embeddings into a sentence-level vector, making it much more suitable for document or chunk-level embeddings. Sentence Transformers models are easy to use and freely available on HuggingFace.
Key Differences:
•
BERT: Embeds each token individually.
•
Sentence Transformers: Pools token embeddings into a single vector per sentence/document.
Why Use Sentence Transformers in Document Embeddings?
Document embedding is the process of converting large chunks of text into numerical vectors that capture semantic meaning. These vectors can then be used in various machine learning tasks such as text classification, clustering, or information retrieval for a RAG-based Chatbot.
When working with Sentence Transformers, it’s important to note that they have a context window limit. Typically, the model can only handle around 256 tokens at a time. Any additional tokens beyond this limit are truncated, which may lead to loss of information.
Therefore, splitting the document appropriately to fit into the model’s token limit is essential for capturing the full meaning without truncation.
Text Splitting in Langchain
To ensure we work within the 256-token limit, Langchain provides different text splitters to divide text into smaller chunks:
1. Recursive Character Text Splitter
The RecursiveCharacterTextSplitter is used to split text by characters. It’s particularly useful when breaking down documents into more manageable parts based on certain separators like newlines or spaces.
from langchain.text_splitter import RecursiveCharacterTextSplitter # Initialize the RecursiveCharacterTextSplitter character_splitter = RecursiveCharacterTextSplitter( separators=[" ", " ", ". ", " ", ""], # Define splitting rules chunk_size=1000, # Maximum chunk size in characters chunk_overlap=0 # No overlap between chunks ) # Split the text (in this case, text from a PDF) character_split_texts = character_splitter.split_text(' '.join(pdf_texts)) # Print a sample chunk print(character_split_texts[10]) print(f"Total chunks: {len(character_split_texts)}")
This splitter breaks the text into chunks of 1000 characters, but character-based splitting might not be enough for embedding models like Sentence Transformers, which work based on tokens rather than characters.
Why Character Splitting May Not Work for Embeddings ?
Providing a chunk size of 256 characters to the RecursiveCharacterTextSplitter (or any character-based splitter) won’t guarantee that it will work seamlessly with the embedding model like Sentence Transformers, because characters and tokens are different concepts.
1.
Tokens and Characters Are Different:
•
A token can be a word, part of a word, or even punctuation. For example, the word “embedding” may be one token, while “embed” is a different token. In contrast, characters are individual letters, spaces, or punctuation marks.
•
The Sentence Transformers embedding model operates on tokens, not characters. So if you split text based on characters, the number of resulting tokens could vary greatly depending on the language or structure of the text. For example, 256 characters might correspond to fewer or more than 256 tokens.
If you split the text into 256 characters per chunk, some chunks may contain more than the allowed 256 tokens when processed by the embedding model, especially if the characters correspond to multiple tokens. The model will truncate any tokens that exceed its context window (typically 256 tokens), leading to loss of information.
2. SentenceTransformersTokenTextSplitter
Since Sentence Transformers embed text based on tokens rather than characters, we need to split our text according to token count. For this, we use the SentenceTransformersTokenTextSplitter.
from langchain.text_splitter import SentenceTransformersTokenTextSplitter # Initialize SentenceTransformersTokenTextSplitter with token limit token_splitter = SentenceTransformersTokenTextSplitter( chunk_overlap=0, # No overlap between chunks tokens_per_chunk=256 # Maximum number of tokens per chunk ) # Split the text into token-based chunks token_split_texts = [] for text in character_split_texts: token_split_texts += token_splitter.split_text(text) # Print a sample chunk after token-based splitting print(token_split_texts[10]) print(f"Total chunks: {len(token_split_texts)}")
Key TakeAway:
•
RecursiveCharacterTextSplitter splits based on characters, but this approach may not consider the token limit of embedding models.
•
SentenceTransformersTokenTextSplitter ensures that each chunk fits within the 256-token limit, making it compatible with the Sentence Transformers embedding model.
This way, we capture all the information in each chunk, avoiding truncation.
How to Use Sentence Transformers from HuggingFace
To use Sentence Transformers for embedding, we can easily load the model from HuggingFace:
from sentence_transformers import SentenceTransformer # Load the pre-trained Sentence Transformer model model = SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2') # Example text text = "This is an example sentence." # Get embeddings embeddings = model.encode(text) # Print the embedding vector print(embeddings)
This code loads the ‘all-MiniLM-L6-v2’ model, a smaller, faster variant of Sentence Transformers that is available on HuggingFace. You can replace it with any other model from HuggingFace based on your needs.
Key Points to Learn
1.
Understand the Token Limit: Always be aware of the token limit for your embedding model. For Sentence Transformers, this is typically 256 tokens.
2.
Use Appropriate Splitters: Character-based splitters may not consider token limits, leading to truncated embeddings. Use token-based splitters like SentenceTransformersTokenTextSplitter.
Conclusion
Using BERT-based models like Sentence Transformers for document embeddings is a powerful technique, but it comes with certain considerations, such as the token limit. By appropriately splitting text into manageable chunks using SentenceTransformersTokenTextSplitter, you ensure that no information is lost during the embedding process. Always remember to consider the context window of your model when embedding large documents.
