Efficient Categorization with LLMs without Fine-Tuning: A Cosine Similarity and Prompting-Based Approach
A while back at work, I ran into a challenge: I needed to use a language model (LLM) to generate categories without resorting to fine-tuning, relying solely on prompts. The issue is that, as we know, categorization done purely through prompting isn’t always accurate, even when adjusting the generation temperature to reduce randomness in the responses.
It became clear, then, that relying solely on the model’s output based on the user prompt and system prompt wasn’t enough. We needed to add a verification layer to ensure the text was correctly classified.
Fortunately, we had a list that could help with this categorization process. In our context, it was a list of categories already used within the application’s domain. Now the scenario was more defined: we had a prompt, we couldn’t use fine-tuning, and we had a list of existing categories.
My first attempt was to include this list directly in the prompt as a guide for the model to base itself on the predefined categories. However, even with this guidance, the randomness of the responses continued to affect the categorization’s effectiveness. Instead of reusing the provided categories, the model often generated new ones with every run, making standardization and consistency of the process difficult.
It was in this scenario that cosine similarity came in as a possible solution. The idea was to use our list of existing categories as a basis for comparison with the responses generated by the LLM. We directly compared the LLM response text with each existing category using cosine similarity (similaridade de cosseno), a widely used metric in natural language processing that measures how similar two texts are based on word distribution.
However, to make this comparison more effective, we had to adapt the strategy. Instead of asking the LLM to return a category directly, we started requesting that it generate a description of the ideal category for that case. With this more detailed description, the cosine similarity comparison became more accurate, allowing us to identify the closest category within our existing list.
This resulted in the following workflow:
With the LLM responses being a description, I fed this output into the cosine similarity algorithm along with our list of existing categories. Then, the comparison is performed. If the similarity with any existing category is sufficiently high, according to a predefined threshold, we reuse that category. Otherwise, a new request is made to the LLM, passing the original description and asking it to create a new category. The newly generated category is then added to the set, becoming available for future comparisons.
This process allowed us to maintain category consistency over time, reducing the unnecessary creation of new categories and increasing the reuse of already mapped concepts.
We saw, then, that it’s not always necessary to resort to fine-tuning to achieve greater efficiency. In scenarios with data, cost, or time limitations, it’s possible to combine traditional techniques with generative AI quite effectively. There are various established algorithms that can complement generative AI and help solve practical problems in our day-to-day work, with greater control and consistency in the results.
