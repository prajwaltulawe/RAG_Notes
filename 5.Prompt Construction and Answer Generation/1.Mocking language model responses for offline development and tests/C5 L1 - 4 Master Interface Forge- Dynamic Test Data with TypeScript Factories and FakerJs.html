Interface Forge: A TypeScript/JavaScript Library to Generate Test Data and Fixtures
In this article, I introduce Interface Forge and discuss some of its use cases, in what I like to think of as “mock driven development”.
Note regarding TypeScript: Interface Forge is written in TypeScript and it offers strong TS support. As such all the examples below use TS as a basis, but this doesn’t mean you cannot use the library using plain JS, which you can of course do.

Using Mock Data for Rapid Prototyping
The final use case I’d like to discuss here is the use of mock data in order to move more rapidly across different components of a codebase - e.g. frontend and backend, or different micro-services that need to communicate.
Simply put: mocking data allows developers working on different components to agree on the interface between their respective components or modules, i.e. the “shape” of the data, and then proceed independently of each other - to a certain extent at least.
Let’s say we agreed that the Backend will supply to the Frontend a user object at a given API endpoint. This endpoint is not yet implemented, but this should not be a blocker for the frontend developer to prototype the user-profile page.

Summary
In this article, I introduced Interface Forge - a TypeScript/JavaScript library for generating mock data and fixtures. In doing so I gave some use cases and testing examples, and discussed some examples of “mock driven development”. Namely, to develop using mock data, facilitating faster prototyping and better testing.
