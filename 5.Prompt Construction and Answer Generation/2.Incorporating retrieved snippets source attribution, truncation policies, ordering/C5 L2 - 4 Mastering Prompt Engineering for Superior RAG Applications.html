Tricks for Getting Desired Output from LLMs in RAGs: Purely Anecdotal
There are multiple sources on learning “Prompt Engineering”. This blog is not about “How to prompt” and I assume you already know the basics of LLMs and prompting. In this write-up, I mention a few techniques I use, especially for RAG applications, which have worked for my specific use case. Although it’s purely anecdotal and specific to my RAG application, I hope this might help you in getting the desired output/generation/inference from LLMs. Most of the experiments were done using llama-2 (small LLM in the rest of this blog), ChatGPT-3.5 and Gemini 1.0 (large LLMs in the rest of this blog), but the observations were similar across the LLMs.
Always give an output format
Providing an output format improved my experience of getting desired output by many folds. Even if the prompt is simple, LLMs may face difficulty in following the instructions. An example of output format is given in the figure below. Adding what to expect in the output format further improved the quality of output. Furthermore, leaving the format empty under-performs compared to providing expectations for each field in the output format. Large LLMs can also provide more complex output formats like json, however, I find that small LLMs are inconsistent with specific formats (e.g. json). Thus, I give the format and parse the LLM output as required. When the number of data fields is large, even ChatGPT and Gemini may output incomplete json (which needs parsing, so I keep it as simple text).
..... Remember the Output Format: Name:name of the person Age:Age of the person Salary:annual salary of the person
Few Shot (at least one shot) works wonders
The biggest gains in my experience after providing the output format was giving some examples. Although it might not be possible in some use cases (e.g. providing a summary of a news article as it might increase the token length and therefore cost), it worked well for my use case which primarily focused on extracting relevant information from the input text. Increasing the number of examples improved the output quality, but it is important to keep the examples diverse to avoid biases from frequent words (tokens) in the prompt. Make sure that the examples are not empty or placeholders. A peculiar observation I had was when I just gave the output format in the example and left the examples empty, even large LLMs hallucinated and output gibberish. So avoid providing empty examples.
.... Examples: Input: paragraph 1 Output: Name:A Age:N Salary:S Input: paragraph 2 Output: Name:A Age:N Salary:S ------------------- Remember the Output Format: Name:name of the person Age:Age of the person Salary:annual salary of the person

Surprisingly, the latter one performs much better than the former method. This could be because of how the LLMs first “learn” what and how to output and then proceed to use the input given by the user for inference by following the same pattern it learned.

Increasing the temperature leads to longer output
Increasing the temperature means that LLMs become more “creative”. As the temperature increases, randomness in picking the next token increases, thus the variability in response increases (thereby it becomes more creative). In other words, if an LLM wants to output a sentence, for higher temperature it takes time for it to reach the logical conclusion of that sentence (and shorter time when temperature is low) as the odds of quickly finding the End Of Sentence (EOS) token decreases. Therefore, reducing the temperature can lead to stable and shorter outputs which is desirable in RAG applications. If you are looking for creative ideas or you need variability (generating simulation data), then higher temperature might be more useful.
Emphasizing to direct LLM output
Emphasizing can be useful. I have found these may or may not work. We can emphasize using delimiters (e.g. do not output any product name or capitalization (DO NOT OUTPUT ANY PRODUCT NAME). I’m not sure which LLMs consider capital and small letters as different tokens but I found this to be mildly helpful. One method which works the best for me is repeating the instructions multiple times if I want to emphasize that point. (e.g. DO NOT OUTPUT ANY PRODUCT NAME, DO NOT OUTPUT ANY PRODUCT NAME, DO NOT OUTPUT ANY PRODUCT NAME).
.... DO NOT OUTPUT SALARY IF NOT GIVEN IN PARAGRAPH. DO NOT OUTPUT SALARY IF NOT GIVEN IN PARAGRAPH. DO NOT OUTPUT SALARY IF NOT GIVEN IN PARAGRAPH. Examples: -------- Remember the output format: ..... Paragraph: {input paragraph}
Providing "things to remember when answering"
One of the bigger differences I found when using smaller vs larger LLMs is their ability to follow the instructions. Providing a list of instructions yielded better results for me. After the prompt and before the examples, I provide a “things to remember when answering” section and it works well in following the instructions (2–3 instructions for small LLMs and 5–6 instructions for large LLMs).
.... DO NOT OUTPUT SALARY IF NOT GIVEN IN PARAGRAPH. DO NOT OUTPUT SALARY IF NOT GIVEN IN PARAGRAPH. DO NOT OUTPUT SALARY IF NOT GIVEN IN PARAGRAPH. Things to remember when answering: 1. include the first name of the person 2. include only the name mentioned in the paragraph. .... Examples: -------- Remember the output format: .....
