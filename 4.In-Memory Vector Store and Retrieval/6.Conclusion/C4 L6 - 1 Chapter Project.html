Chapter Project
Context
You are a student working on a personal project to organize your study notes using vector search. You’ve learned about in-memory vector stores in TypeScript, and now you need to apply these concepts to build a practical tool that helps you quickly find relevant notes based on semantic similarity, combining vector search with metadata filters like subjects and dates.
Build a TypeScript in-memory vector store for your study notes. Your goal is to create a system that stores note embeddings and metadata, allows adding, updating, and deleting notes, and retrieves the most relevant notes for a query using a retrieval pipeline that combines vector similarity with metadata filtering. Follow these steps: 1) Design and implement an in-memory vector index in TypeScript. Define clear interfaces for vectors, documents, and metadata. Choose appropriate data structures like arrays or typed arrays. Handle validation for vector dimensionality. 2) Implement index flows: create functions to add, update, and delete notes. Maintain mappings between IDs, vectors, and documents. Handle partial failures and ensure consistency. 3) Implement similarity search: start with a brute-force top-k search using cosine distance. Include batch queries and early termination if needed. 4) Build a retrieval pipeline: design an interface that combines vector scores with metadata filters (e.g., filter by subject='math' or date range). Implement ranking by score, recency, or other fields. Add pagination, limits, and tie-breaking rules. 5) Test and benchmark: write unit tests for distance logic and scoring. Create a deterministic golden dataset for testing. Write microbenchmarks for hot search paths and measure latency and memory usage. Use the provided CSV file at https://example.com/study_notes.csv, which contains 100 study notes with fields: id, title, content, subject, date, and a precomputed embedding vector (as a comma-separated list of 384 floats). Load this data into your vector store. Constraints: Use only TypeScript and Node.js. Do not use external vector databases or paid services. Assume embeddings are precomputed and provided in the CSV. Your code must be modular with separate modules for index, search, pipeline, and tests. Acceptance criteria: Your system must correctly store all notes, retrieve the top 5 most similar notes for a sample query 'machine learning algorithms', filter results by subject='computer science', and rank them by score and recency. It must pass all unit tests and show benchmark results for search latency under 50ms for 100 notes. Evidence/output: Submit your TypeScript code files, a README with setup instructions, and a brief report explaining your design decisions (e.g., why you chose specific data structures or algorithms). You can paste your answer into the designated text field or upload a .txt file in the appropriate section on this page.
