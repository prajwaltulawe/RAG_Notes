Implementing RAG with HNSW via FAISS
Retrieval-Augmented Generation (RAG) enhances language model generation by incorporating external knowledge. This is achieved by retrieving relevant information from a massive corpus of documents and using that information in the generation process. The language model uses a retriever to find relevant contexts that condition the model, thereby augmenting its knowledge base with pertinent documents. There are many types of retrievers available depending on the context: vector databases, graph databases, or standard SQL databases. One common issue with vector databases is that the retrieved data can sometimes be irrelevant. Vector databases store data, partition and index it, and retrieve it using semantic similarity. In contrast, graph databases build a knowledge base from extracted entity relationships, resulting in more precise retrieval. Below are the key stages in a RAG process:
· RAG begins by converting datasets into vectors and storing them in a vector database.
· The user submits a natural language query seeking an answer or completion.
· The retrieval mechanism scans the vector database to identify segments semantically similar to the user query.
· The selected segments are then combined with the user’s original query.
· This augmented input, with added context, is sent to the LLM to generate a more relevant response.
The main stages of RAG are as follows:
Ingestion: The ingestion phase starts by chunking input documents into segments based on a fixed size, such as a specific number of characters, sentences, or paragraphs.
Embedding: Once chunked, the documents are embedded into the knowledge base in a format that enables effective relevance matching.
Retrieval: In a basic RAG pipeline, chunks with the highest similarity scores to the input query are retrieved from the database.
Synthesizing: The retrieved chunks and user input are fed to a large language model to synthesize the information and generate a coherent response.
Importance of a Vector Store in RAG
· The vector store enables the RAG model to quickly retrieve information from a large corpus.
· It is designed to handle large-scale datasets efficiently.
· It plays a key role in retrieving context that enriches the generation process.
· Vector embeddings capture the underlying meaning of the text, enabling semantic search that is more flexible and accurate than keyword-based search.
The most critical aspect of RAG is identifying the most relevant chunk to answer the user’s question. To address the computational cost of processing irrelevant documents, HNSW dramatically reduces the time needed to find the most similar chunks compared to a brute-force search across all embeddings. HNSW efficiently searches high-dimensional spaces using a small-world network concept, which posits that most natural networks can be traversed in just a few steps. HNSW constructs a multi-layer graph to index high-dimensional vectors. Each node represents a vector, with edges connecting to its nearest neighbors. When a query vector is introduced, HNSW navigates the graph to find the most similar vectors based on a distance metric.
The HNSW algorithm performs ANN (Approximate Nearest Neighbor) searches in vector databases, balancing speed and accuracy. HNSW is a graph-based indexing algorithm combining two concepts: probabilistic skip lists and Navigable Small World (NSW) graphs.
What is a Probabilistic Skip List?
A probabilistic skip list is a multi-level linked list where upper levels have long-range connections. As you descend the layers, connections shorten, with the bottom layer being the original sequential list. It addresses the time and space complexity issues of traditional linked lists. Skip lists work only with sorted lists, requiring direct comparison of object magnitudes. Once you find a node for an element greater than ‘n’ in the list, you backtrack to the previous layer below. This continues until the element is located.
What is Navigable Small World (NSW)?
NSW is a graph-based algorithm that views graphs in terms of short, medium, and long edges. Vector search starts at an entry point and greedily moves toward the nearest point closer to the target. In vector search terms, all vectors in the dataset form points on an NSW graph, with long-range connections between dissimilar vectors and short-range connections between similar ones. Vector similarity is measured using metrics like L2 distance (Euclidean distance) or inner product (IP) for floating-point vectors, and Jaccard or Hamming distance for binary vectors. However, vector databases typically handle millions of data points, not hundreds.
Hierarchical Navigable Small World (HNSW)
HNSW extends NSW by integrating it with skip lists, maintaining multiple layers of NSW graphs. The topmost layer has few nodes and the longest links, while the bottom layer includes all nodes with the shortest links. During search, you start at a predefined entry point in the top layer and greedily route toward the nearest neighbor to your query vector. For a vector ‘v’, you first traverse the top layer to find its nearest neighbor, then move to the layer below and repeat. This continues until reaching the nearest neighbor in the bottom layer.
