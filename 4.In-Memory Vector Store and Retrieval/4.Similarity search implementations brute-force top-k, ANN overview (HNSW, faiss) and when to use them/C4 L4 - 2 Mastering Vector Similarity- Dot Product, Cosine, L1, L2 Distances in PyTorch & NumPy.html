Understanding Vector Similarity for Machine Learning
Cosine Similarity, Dot Product, Manhattan Distance L1, Euclidean Distance L2.
Similarity measures play a crucial role in machine learning. These measures quantify the similarity between objects, data points, or vectors in a mathematical manner. Understanding the concept of similarity in the vector space and employing appropriate measures is fundamental in solving a wide range of real-world problems, such as recommendations or feature importance. There are several similarity measures that can be used to calculate how close two vectors are in the embedding space.
![Figure 1: Embedding Space Figure by Author]
Dot Product
The Dot Product is a commonly used similarity metric. The dot product measures both directional similarity and magnitude of vectors. It’s particularly useful when both the direction and size of vectors carry meaningful information. It always returns a single scalar (number). Dot Product values can range from negative infinity to positive infinity, with negative values indicating opposite directions, positive values indicating the same direction, and a value of 0 when the vectors are perpendicular. Larger Dot Product values indicate greater similarity (See Figure 3).
dot_product(a,b) = Σ(aᵢ × bᵢ) = a₁b₁ + a₂b₂ + ... + aₙbₙ
Geometrically, it can be expressed as:
dot_product(a,b) = |a| × |b| × cos(θ)
where |a| and |b| are the magnitudes (lengths) of the vectors, and θ is the angle between them. Figure 3 illustrates the calculation of the Dot Product between Point P1 and the remaining Points P2 to P5. It also compares the dot product to cosine similarity.
Cosine Similarity
Cosine Similarity only considers the angle between vectors, regardless of their magnitude (length). To calculate the cosine similarity between two vectors, one can simply divide the dot product of both vectors by the product of their lengths. This scales the vector magnitudes to 1. Thus cosine similarity is invariant to vector magnitude. It’s particularly useful when you want to compare vectors based purely on their directional similarity.
cosine_similarity(a,b) = dot_product(a,b) / (|a| × |b|)
Using PyTorch to calculate cosine similarity:
import torch import torch.nn.functional as F # Method 1: Using F.cosine_similarity cos_sim_1 = F.cosine_similarity(vector1, vector2) # Method 2: Manual calculation cos_sim_2 = torch.dot(vector1, vector2) / (torch.norm(vector1) * torch.norm(vector2))
We can see the calculations in Figure 2. Here we see that point A(1.5, 1.5) and point B(2.0, 1.0) are close together in a 2-dimensional embedding space. When we calculate the cosine similarity, we obtain a value of 0.948, confirming that both vectors are quite similar. In contrast, when we compare the similarity of point A(1.5, 1.5) and point C(-1.0, -0.5), we observe that the cosine similarity is -0.948, indicating that both vectors are dissimilar. We can see that they are in opposite directions in the embedding space. A cos(θ) value of 0 would indicate that both vectors are perpendicular to each other, showing neither similarity nor dissimilarity.

Relationship between Dot Product and Cosine Similarity
Both the Dot Product and Cosine Similarity are closely related concepts.
![Figure 3: Comparison between Dot Product and Cosine Similarity Figure by Author]
The Dot Product can be derived from the cosine equation: by multiplying the cosine of the angle between two vectors by the lengths of both vectors, we obtain the Dot Product, as depicted in Figure 4. Consequently, the Dot Product is influenced by the magnitude of vector embeddings, which can be a crucial consideration when choosing similarity measures. Larger magnitudes will result in a larger dot product, even if the angle between the vectors remains the same. The dot product of normalized vectors is the cosine similarity! Because the magnitude in normalised vectors is 1!
![Figure 4: Cosine & DotProduct Figure by Author]
If you normalize your vectors (make them all length 1) before comparing them, the Dot Product and Cosine Similarity become identical.
Cosine similarity primarily considers the direction cos(θ) of the vectors independent of length. Because cosine similarity normalises the dot product by dividing it by the product of the vector length.
In contrast, the dot product is highly sensitive to the length of the vectors. If some vectors have greater length then the direction cos(θ) becomes less relevant.

Dot Product # Returns a scalar (single number) dot_prod = torch.dot(vec_a, vec_b) # Calculation: 1*5 + 2*4 + 3*3 + 4*2 + 5*1 = 35.0 # 2. Cosine Similarity # dim=0 because these are 1D vectors cosine_sim = F.cosine_similarity(vec_a, vec_b, dim=0)
In modern NLP, you rarely process one vector at a time. You usually have a matrix of embeddings (e.g., [Batch_Size, Hidden_Dim]).
Here, torch.dot will not work (it only accepts 1D tensors). You must use matrix multiplication (matmul or @) or element-wise multiplication summing.
# Query: 1 vector (1x3) query = torch.tensor([[1.0, 1.0, 1.0]]) # Database: 3 documents (3x3) documents = torch.tensor([ [1.0, 2.0, 3.0], [1.0, 1.0, 1.0], [0.0, 0.0, 1.0] ]) # Dot Product # Use Matrix Multiplication (@ or torch.matmul) # We transpose documents (T) to align shapes: (1x3) @ (3x3) -> (1x3) scores = query @ documents.T
Understanding cos(θ) in the dot product and cosine similarity
Theta (θ) is just the angle in degrees between vectors. But we do use cosine because it naturally maps to similarity (-1 to 1). On the other hand, one can convert the similarity value, cos(θ), to the angle measured in degrees between the two vectors (θ) by taking the inverse cosine.
import torch import torch.nn.functional as F import math #Create 3 Vectors A = torch.tensor([1.5,1.5]) B = torch.tensor([2.0,1.0]) # Calculate cosine similarity cos(𝜃): cos = F.cosine_similarity(A, B, dim=0) print("Cosine Similarity:", cos) # Calculate the angle 𝜃: # acos is the inverse of cos(x) and returns angle in radians theta = math.acos(cos) # Convert radians to degrees by multiplying with (180/π) theta_degrees = math.degrees(theta) print("Angle in radians:", theta) print("Angle in degrees:", theta_degrees)
Manhattan (L1) and Euclidean (L2) Distance
Manhattan distance calculates distance by summing the absolute differences along each dimension, whereas Euclidean distance calculates the straight-line distance between points.
Manhattan distance is suitable for scenarios involving grid-like movement or when individual dimensions have varying importance. On the other hand, Euclidean distance is ideal when measuring the shortest path or when all dimensions contribute equally to the distance.
In most cases, Manhattan distance produces larger values than Euclidean distance for the same pair of points. As the data dimensionality increases, Manhattan Distance becomes the preferred choice compared to the Euclidean distance metric [1].

Comparing Vectors of different Dimension
It is important that we only compare vectors of the same dimension. The reason we need the same dimensions is that each dimension typically represents a specific feature (in our case, a specific word). If we have vectors of different dimensions, say one 3-dim: [32,41,1] and one 4-dim: [1,42,67,2], then we can pad the vector with the smaller dimension, by adding a zero to the missing dimension. So then we get [32,41,1, 0] vs. [1,42,67,2]
