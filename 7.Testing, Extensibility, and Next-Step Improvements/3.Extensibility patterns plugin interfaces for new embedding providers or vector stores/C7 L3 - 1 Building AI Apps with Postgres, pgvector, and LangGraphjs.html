Postgres + pgvector: The Battle-Proven Vector Store for Full-Stack AI Applications
The first question I get when I introduce the PLAN stack is: "Why Postgres?"
In the world of AI-first applications, choosing the right vector store is one of the most critical architectural decisions. While many new databases promise cutting-edge features, there’s a strong case for relying on a trusted foundation: Postgres with pgvector.
As part of the PLAN stack, Postgres isn’t just another database - it’s a strategic choice. Let’s explore the motivations and benefits.

Introducing the PLAN Stack: The Toolkit for Full-Stack AI Engineers
Why Postgres?
Postgres has been in production for decades, powering applications at massive scale across industries. It is:
•
Stable and Reliable: ACID compliance, strong consistency, and robustness under heavy load.
•
Mature and Well-Supported: Rich tooling, drivers, and a global community that has solved countless edge cases.
•
Operationally Familiar: Teams already know how to deploy, scale, replicate, and monitor it - avoiding the learning curve of “exotic” databases.
This maturity ensures that when AI applications move from prototype to production, Postgres provides a battle-proofed, enterprise-ready foundation.
pgvector: Modern Vector Capabilities on a Familiar Base
The pgvector extension brings vector similarity search directly into Postgres. With it, you can:
•
Store embeddings alongside relational data in one unified system.
•
Run hybrid queries that combine semantic similarity with structured SQL filters.
•
Leverage SQL syntax and existing tooling for managing vectors and metadata.
This avoids the complexity of running both a relational database and a separate vector store, keeping everything under one roof.
Technical Benefits
1.
Single Source of Truth Embeddings and application data live in the same database - no syncing issues.
2.
SQL + Vectors Together Harness the power of joins, filters, and aggregates alongside semantic search.
3.
Transaction Safety Inserts, updates, and vector operations are fully atomic.
4.
Flexible Indexing Choose precise search or approximate nearest neighbor (ANN) for speed.
5.
Operational Efficiency Scale, replicate, and back up vectors the same way as any Postgres table.

Integration with LangGraph.js
LangGraph.js can use Postgres as its persistence and memory layer. Here’s a minimal example - focused on Postgres integration:
import { PostgresSaver } from "@langchain/langgraph-checkpoint-postgres"; import { Pool } from "pg"; import { StateGraph, MessagesState } from "@langchain/langgraph"; // PostgreSQL Setup - This is the focus const pool = new Pool({ connectionString: "postgresql://user:password@localhost:5432/database" }); const checkpointer = new PostgresSaver(pool); await checkpointer.setup(); // Creates PostgreSQL tables // Minimal echo graph const graph = new StateGraph(MessagesState) .addNode("echo", (state) => ({ messages: [{ role: "assistant", content: `Echo: ${state.messages.at(-1).content}` }] })) .addEdge("__start__", "echo") .addEdge("echo", "__end__") .compile({ checkpointer }); // 👈 PostgreSQL persistence enabled // Usage - conversation persisted in PostgreSQL const config = { configurable: { thread_id: "chat-1" } }; await graph.invoke({ messages: [{ role: "user", content: "Hello!" }] }, config); await graph.invoke({ messages: [{ role: "user", content: "Remember this?" }] }, config); // ☝️ Full conversation history automatically saved to PostgreSQL
This example shows:
•
PostgreSQL-backed persistence for conversation state.
•
Thread-based message storage that survives application restarts.
•
Zero-configuration checkpointing - just add the checkpointer and conversations are automatically saved.
Using Embeddings with pgvector and LangGraph.js
LangChain’s PGVectorStore makes it simple to store and query embeddings in Postgres. Here is a simple example of how to create a vector store:
import { PGVectorStore, DistanceStrategy, } from "@langchain/community/vectorstores/pgvector"; import { OpenAIEmbeddings } from "@langchain/openai"; import { PoolConfig } from "pg"; const embeddings = new OpenAIEmbeddings({ model: "text-embedding-3-small", }); // Sample config const config = { postgresConnectionOptions: { type: "postgres", host: "127.0.0.1", port: 5433, user: "myuser", password: "ChangeMe", database: "api", } as PoolConfig, tableName: "testlangchainjs", columns: { idColumnName: "id", vectorColumnName: "vector", contentColumnName: "content", metadataColumnName: "metadata", }, // supported distance strategies: cosine (default), innerProduct, or euclidean distanceStrategy: "cosine" as DistanceStrategy, }; const vectorStore = await PGVectorStore.initialize(embeddings, config);
Then, this vector store can be used like any other vector store in LangChain:
import { v4 as uuidv4 } from "uuid"; import type { Document } from "@langchain/core/documents"; // create some mock documents to embed const document1: Document = { pageContent: "The powerhouse of the cell is the mitochondria", metadata: { source: "https://example.com" }, }; const document2: Document = { pageContent: "Buildings are made out of brick", metadata: { source: "https://example.com" }, }; const document3: Document = { pageContent: "Mitochondria are made out of lipids", metadata: { source: "https://example.com" }, }; const document4: Document = { pageContent: "The 2024 Olympics are in Paris", metadata: { source: "https://example.com" }, }; const documents = [document1, document2, document3, document4]; const ids = [uuidv4(), uuidv4(), uuidv4(), uuidv4()]; await vectorStore.addDocuments(documents, { ids: ids });
Performing a simple similarity search can be done as follows:
const filter = { source: "https://example.com" }; const similaritySearchResults = await vectorStore.similaritySearch( "biology", 2, filter ); for (const doc of similaritySearchResults) { console.log(`* ${doc.pageContent} [${JSON.stringify(doc.metadata, null)}]`); }
LangGraph nodes can directly call vectorStore methods. This enables retrieval-augmented workflows where nodes query vector databases during graph execution:
import { StateGraph, Annotation } from "@langchain/langgraph"; // Assume vectorStore is already initialized (see previous example) const StateAnnotation = Annotation.Root({ query: Annotation(), docs: Annotation>(), }); const graph = new StateGraph(StateAnnotation) // Node that calls pgvector directly .addNode("search", async (state) => { // Direct vectorStore call from LangGraph node const results = await vectorStore.similaritySearch(state.query, 3); return { docs: results.map(doc => ({ content: doc.pageContent, metadata: doc.metadata })) }; }) .addEdge("__start__", "search") .addEdge("search", "__end__") .compile(); // Usage const result = await graph.invoke({ query: "How does pgvector work?", docs: [] }); console.log(`Found ${result.docs.length} relevant documents`);
