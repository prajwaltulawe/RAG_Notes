Numerical Authority Weights Override Semantic Bias in Multi-Document LLM Prompts
A technique for controlling which source an LLM trusts when documents contradict each other - tested across 9 runs on Claude Sonnet 4.6.
When you give an LLM multiple documents that contradict each other, which source does it trust? Usually, the one that sounds most authoritative - regardless of whether it actually is.
I ran an experiment testing whether you can override this by assigning explicit numerical authority scores to documents, using mathematical notation and a formal conflict resolution function. The short version: it works for a specific and practically important failure mode, it doesn’t work for what I originally thought, and the most interesting behavior was something I didn’t expect.
The Problem
Multi-document RAG systems have a source trust problem. When retrieved chunks disagree, the model has to decide which one to believe. In the absence of explicit guidance, it relies on heuristics: recency cues, confident language, precise numbers, and status words like “approved” or “confirmed.”
These heuristics are usually fine. But they break when an outdated source happens to sound more authoritative than a current one - when the wrong answer is wrapped in better packaging.
The Setup
I created five fictional documents for a biotech company, each containing overlapping metrics (revenue, headcount, clinical trial results) with slightly different numbers. The correct information was always in Document 3 - a Scientific Advisory Board meeting minutes placed in the middle of the context window.
The trap: Document 3 used hedged, procedural language (“approximately,” “preliminary,” “pending negotiation”). Documents 1 and 5 - at the beginning and end of the context - used confident, precise, declarative language. One metric was specifically designed to test whether the model could resist a consensus trap: two documents agreed on an outdated cash figure ($412M), while the single authoritative source reported a different number ($389M).
The hardest question was the 2026 operating budget. Document 5 (an annual report draft) described a $195M budget as “board approved.” Document 3 (the SAB minutes) described a ~$210M budget as “preliminary, pending Lonza contract negotiation.” For a model relying on language cues, “board approved” beats “preliminary” every time.
The Technique
I tested three conditions with 3 runs each (9 total chats on Claude Sonnet 4.6):
Prompt 1 - Control. All five documents provided with no hierarchy. “Use your best judgment” for conflicts.
Prompt 2 - Authority Weights. Same documents, but each tagged with a numerical authority score and a mathematical conflict resolution function:
DOCUMENT AUTHORITY MATRIX:
Let A(Dn) = authority weight of Document n, where A ∈ [0.0, 1.0]
A(D1) = 0.35 → Investor fact sheet - public-facing, may use rounded figures A(D2) = 0.30 → Corporate website - marketing copy, often lags behind data A(D3) = 0.95 → SAB meeting minutes - unblinded internal data, most current A(D4) = 0.55 → Analyst report - external, based on public data only A(D5) = 0.40 → Annual report draft - finance summary, may use earlier data
CONFLICT RESOLUTION: ∀ Di, Dj where i ≠ j: if A(Di) > A(Dj) AND Di states a different value than Dj → use Di if A(Di) - A(Dj) > 0.3 → Dj's conflicting value is DISCARDED without mention if A(Di) - A(Dj) ≤ 0.15 → present both values and flag the discrepancy
No explicit retrieval instruction (“search D3 first”) was included. The authority numbers alone had to do the work.
Prompt 3 - Authority + Consensus Trap Warning. Same as Prompt 2, plus an explicit rule that agreement among low-authority sources does not override a high-authority source.
Results
Nine questions per run. The correct answer for eight of them came from Document 3 (middle position).
The control was much stronger than expected - it correctly identified the SAB minutes as the best source for 7 out of 8 questions without any authority guidance. It detected recency from contextual cues (payroll dates, data cutoff dates, meeting structure) rather than needing explicit help.
But it consistently failed on one question: the budget. Every control run picked $195M (“board approved”) over ~$210M (“preliminary”). The model’s natural reasoning treated the word “approved” as a stronger signal than the source’s actual reliability.
The authority weights fixed this in every weighted run. The math was straightforward: A(D3) - A(D5) = 0.55 > 0.30, so D5’s value was discarded regardless of its “approved” label. Six runs, six correct answers.
The consensus trap warning produced a null result for accuracy. The control already resisted the $412M consensus (D1 + D4 agreeing) in all 3 runs without being warned. The warning made the model explain why it resisted (“textbook Consensus Trap - they share a common public data source”) but didn’t change any answers. Useful for auditability, not for accuracy.
How the Model Processed the Weights
A notable behavior: the model treated the conflict resolution function as a decision procedure. In every authority-weighted run, before answering, the model explicitly calculated authority deltas between document pairs:
“D3 − D5 = 0.55 > 0.30 → D5 discarded.”
“D3 − D4 = 0.40 > 0.30 → D4 discarded.” It didn’t just follow the weights as a general guideline. It ran the conditional logic pair-by-pair, applied the threshold, and structured its entire response around the mathematical framework. This is likely pattern completion - models routinely echo back structured reasoning formats - rather than genuine mathematical execution. The important thing is not whether the model “understood” the math but that the behavioral output was consistent: 6 runs, 6 times the delta logic appeared in the reasoning, 6 correct answers on the question the control failed.
What This Doesn’t Prove
It doesn’t prove authority weights override positional bias. The original hypothesis was that mathematical authority scores could rescue information from the “lost in the middle” attention dead zone. The control scored 7.33/8 on middle-zone retrieval without any help - Sonnet 4.6 is already good at this. The experiment couldn’t isolate a positional bias effect to override. Testing this properly would require a longer context, more documents, or a less capable model where positional effects are stronger.
It doesn’t prove mathematical notation is better than prose. I didn’t test whether A(D3) = 0.95 produces different behavior than “Document 3 is the most reliable source.” The authority weights might work purely because they’re explicit instructions, not because the numbers add anything. A direct comparison is needed.
It doesn’t prove the mechanism. The model may be pattern-matching on numerical importance from training data (rubrics, priority matrices, severity ratings). Or it may just be following explicit instructions that happen to use numbers. The behavioral result is the same either way, but the theoretical interpretation is different.
What It Does Prove
Authority weights fix a specific, reproducible failure mode: when a low-reliability source uses confident status language that the model’s default reasoning prefers over a high-reliability source with hedged language.
This is not an edge case. In real-world RAG systems, outdated documents routinely sound more authoritative than current ones. A 2023 policy document says “the approved rate is 4.5%.” A 2025 internal memo says “the rate is approximately 3.8%, pending final confirmation.” Without authority weights, the model trusts the confident outdated source. With authority weights, it trusts the correct one.
The technique is simple to implement: tag each document with an authority score in the system prompt, add a conflict resolution rule with a delta threshold, and let the model apply it. No additional infrastructure, no fine-tuning, no embedding changes. It’s a prompt-layer fix for a retrieval-layer problem.
How to Use This
If you’re building a multi-document RAG system where sources have different reliability levels:
1.
Assign each source type an authority score (0.0–1.0) based on its actual reliability in your domain
2.
Tag retrieved chunks with their authority score in the prompt
3.
Include a conflict resolution function with explicit thresholds
4.
Do NOT include an explicit retrieval order - let the weights do the work
The threshold > 0.3 → discard worked well in this test, but the optimal threshold likely depends on the domain and the model. Test it.
Limitations
This was tested on one model (Claude Sonnet 4.6), one domain (biotech documents), with 3 runs per condition (9 total). The sample size is above n=1 but below statistical rigor. The control’s strong baseline performance (7.33/8) means the authority weights only demonstrably helped on 1 out of 8 questions - though that one question was the hardest and most practically important.
Replication across models, domains, and larger sample sizes is needed before this can be stated as a general technique. How This Was Made
I’m 18, finishing technical high school in Serbia. I had a simple idea: LLMs are math under the hood, so what if you use math in the prompts instead of just writing instructions? That’s it. That was the whole starting point.
I didn’t know how to design experiments, write research-style documents, or build conflict resolution functions with mathematical notation. So I used Claude as a thinking partner across multiple conversations. Here’s what was me and what was AI:
Me: The original idea. Asking the right questions. Running all 9 test chats manually. Checking if results actually made sense. Pushing back when the first experiment design was too easy (V1 had obvious cues that made the test trivial). Deciding what to cut - there was a full 446-line framework paper that I scrapped because the evidence didn’t support it. Deciding to ship this focused version instead.
AI (Claude): Designing the experiment. Writing all five fictional Helion Therapeutics documents. Building the three test prompts including the authority matrix and conflict resolution function. The mathematical notation itself. Structuring the analysis. Most of the text you’re reading was written by AI based on my direction.
I’m not a researcher, I’m not a mathematician, and I didn’t write this paper by hand. I had an intuition, I used AI to explore it as far as I could, and the result was a real finding that someone with more experience can replicate and build on.
